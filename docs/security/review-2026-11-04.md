# Security review — Althera — 2026-11-04

Manual source review, dependency audit, isolated HTTP tests and authenticated Supabase metadata inspection. No live charges, transfers, cancellation, financial event replays, credential rotation or customer record modifications performed.

## Confirmed findings and containment

1. **Critical: public CRM and financial database access.** Live pg_policies had permissive public USING true / WITH CHECK true on contacts, invoices, transactions, projects and commercial accounts. RLS enabled alone did not protect them. Applied restrictive boundaries in `restrict-public-access.sql`, after rollback validation. Atomic checks confirmed anonymous/non-admin users cannot read sensitive rows and both verified administrators retain finance access. No data rows were changed. Catalog read and contact-form insert remain public. Service-role backend access remains unchanged. Policies are restrictive so existing permissive setup policies cannot reopen access.
2. **Critical: sensitive Stripe routes lacked admin checks.** Transfer creation, connected-account operations, arbitrary Checkout creation and session reconciliation were reachable without required administrative authorization. A default-deny middleware now protects the entire Stripe route prefix, allowing only signed webhooks, publishable configuration and a minimal read-only return-page status. UI calls send the actual Supabase session. A customer account or forged/unconfirmed token is not an admin.
3. **High: commercial browser password comparison.** Credentials were retrieved with accounts and compared in JavaScript. User explicitly authorized temporarily blocking commercial access. Login is paused and database access restricted. Commercial RPCs now execute as the caller, subject to RLS, instead of bypassing it. Reopening requires a separate authenticated, ownership-scoped migration and credential resets; never restore the previous public policies.
4. **High: server artifacts could be served by Render.** Production static serving now denies server bundles, source maps, source files, logs and hidden files. Hostinger already had a similar boundary.
5. **Hardening:** webhook signature is mandatory and missing configuration fails closed; removed unsigned event-ID fallback. Return-page reads no longer run reconciliation. Removed mock-payment confirmation branch. Payment callback origins no longer trust request Host/Origin headers. Logs omit headers, queries and bearer-link tokens. Corrected Carlos's malformed hardcoded UUID using verified auth.users metadata.
6. **Dependencies:** compatible updates plus html2pdf.js 0.14.0 and jsPDF 4.2.1; brace-expansion 1.1.21 pinned under minimatch 3.1.5. npm audit after installation reports 0 known vulnerabilities. This is not proof of absence of vulnerabilities. Reviewed upstream advisories https://github.com/advisories/GHSA-w8x4-x68c-m6fc and https://github.com/advisories/GHSA-f8cm-6447-x5h2. PDF rendering uses escaped invoice fields / element sources; the server-side jsPDF file-reading vector was not found in app routes.

## Verification

- `scripts/test-payment-access.ts`: anonymous, forged, customer, unconfirmed and provider-outage requests blocked without reaching sensitive operations; admin allowed; public methods scoped; source artifacts denied.
- `scripts/test-web-offers.ts`: ownership checks, server-owned USD prices, consent, checkout locking/reuse; all Stripe calls mocked.
- `scripts/test-public-gateway.ts`: offline landing; auth/cookies/redirects preserved; exact signed webhook bytes retained.
- `scripts/test-branded-links.ts`: admin-only mutation; revoked link handling; no financial side effects.
- Build includes financial regression, 4,336 tax/installment combinations, invoice reconciliation, recurrence, split and commission checks.
- TypeScript, production build and synthetic movement PDF export checked after dependency changes.
- Tracked-source secret scan found no live Stripe secret/restricted key, private key or sb_secret matches. Git history and external logs not fully scanned.

## Outstanding / limitations

- Confirm production rollout and unauthorized-route rejection after push; local source fixes are not live until deployment completes.
- Commercial authentication migration and credential resets remain pending. Exposed commercial passwords should be treated as potentially compromised; no evidence of actual misuse has been established by this review.
- Account MFA/recovery, full historical access-log investigation, all cloud administrators/API keys, and private/public storage contents need separate verification. No guarantee of zero attacks can be made.
- Rate limits and abuse controls for public submission/status endpoints can be strengthened further; keep legitimate public Checkout available.
- Original policy/function metadata captured locally in /tmp/althera-security-baseline.txt; it contains no customer rows. Do not restore it wholesale: it restores insecure public access.

## Hosting scanner observation

Hostinger's report lists two removed `node_modules/html2pdf.js/dist/html2pdf.bundle.min.js.map` files in old build versions (18 and 19 October). These are dependency source maps, not evidence by themselves of account takeover. The package has now been updated and public source maps denied. The deleted originals were not available for content comparison, so malicious modification versus scanner false positive is unresolved. No other file paths were shown in this report.
